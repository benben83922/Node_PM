## 第 2 部分：商業目標 (Business Objectives) - 「為何做？」

*在投入資源前，我們必須清晰地定義問題、目標使用者和商業價值，避免開發出無人需要的產品。*

| 區塊 | 內容 |
| :--- | :--- |
| **1. 背景與痛點** | **市場規模**：台灣超過 167 萬家中小企業 + 80 萬非典型工作者構成龐大的零工經濟市場。<br><br>**核心痛點 - 信任赤字**：<br>- **案主端**：付了錢拿不到東西、交付物不符預期、接案者失聯<br>- **接案者端**：做了事收不到錢、需求無限修改、案主不回應<br>- **雙方**：需求溝通困難、驗收標準模糊、爭議處理無門<br><br>**現有解決方案不足**：<br>- 全球巨頭 (Upwork, Fiverr)：在地化不足、高抽成<br>- 本土競標平台 (PRO360, Tasker)：加劇削價競爭、信任機制薄弱<br>- 免費布告欄 (1111 Case+, PTT)：零平台治理、完全沒有保障 |
| **2. 策略契合度** | **市場定位**：成為市場上第一個「在地化的高信任」解決方案，填補「高風險本土平台」與「高摩擦全球平台」之間的市場空白。<br><br>**策略三大支柱**：<br>1. **產品即信任**：AI 輔助規格產出、里程碑式價金託管、客觀數據驅動的信譽系統<br>2. **利益完全對齊**：僅在專案里程碑成功交付時才收取服務費<br>3. **非對稱上市策略**：優先獲取高質量專案（需求端），以優質案源吸引頂尖人才 |
| **3. 成功指標 (Success Metrics)** | **北極星指標**：每週成功釋款里程碑數<br><br>- **主要指標**：專案成功率（無爭議完成比例）> 95%<br>- **次要指標**：<br>  - 爭議率 < 3%<br>  - POC 轉正式案率 > 70%<br>  - 平均爭議解決時間 < 7 天<br>  - LTV/CAC 比率 > 3 |

## 第 4 部分：範圍與限制 (Scope & Constraints)

*明確定義邊界是專案成功的關鍵。這為 LLM 生成程式碼提供了最重要的「護欄」。*

| 區塊 | 內容 |
| :--- | :--- |
| **功能性需求 (In Scope)** | **MVP 範圍（12 週）**：<br>- 使用者註冊、登入、個人檔案管理<br>- LLM Agent 需求引導（支援網站開發類型）<br>- 動態里程碑建立與管理<br>- 價金託管 API 整合<br>- 基礎驗收流程<br>- POC 概念驗證模式（基本流程）<br>- 牌位系統（積分計算與顯示）<br>- 爭議處理流程 v1 |
| **非功能性需求 (NFRs)** | **性能**：<br>- 頁面載入時間 < 3 秒<br>- API 回應時間 < 500ms<br><br>**安全性**：<br>- 所有密碼使用 bcrypt 加密<br>- HTTPS 全站加密<br>- 敏感資料加密儲存<br><br>**可用性**：<br>- 支援桌面版與手機版響應式設計<br>- 系統可用性 > 99.5% |
| **不做什麼 (Out of Scope)** | **MVP 不包含**：<br>- 多語系支援（僅繁體中文）<br>- 第三方帳號登入（Google/Facebook）<br>- 即時聊天功能（Phase 2）<br>- APP 版本<br>- AI 程式碼審查服務<br>- 專案保險產品<br>- 跨國/多幣別支援 |
| **假設與依賴** | **假設**：<br>- 使用者具備穩定的網路連線<br>- 使用者有基本的電腦/手機操作能力<br>- 台灣金流服務商可支援價金託管模式<br><br>**依賴**：<br>- 金流服務商（需支援 Marketplace 模式）- **最關鍵依賴**<br>- LLM API（Claude/GPT）<br>- 雲端服務（AWS/GCP）<br>- Email 發送服務（SendGrid） |
